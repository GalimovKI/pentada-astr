# Точный косинусный поиск E5 на сервере dev

Веса intfloat/multilingual-e5-small, ONNX INT8, локальны для backend. При подготовке релиза сервер кодирует письма и сохраняет матрицы в постоянный том. На каждый запрос CPU сервера строит вектор с префиксом `query: `. Все доступные письма выбранного ящика получают оценку по косинусу. Неизвестная дата допустима, будущие письма исключены. Поиск использует первые 512 токенов, включая префикс и служебные токены. [Код](https://github.com/GalimovKI/pentada-astr/commit/ea8c2f4b3cebb0b99b230eb9fe93f13d26def5f5) · [Успешный релиз](https://github.com/GalimovKI/pentada-astr/actions/runs/44944855885)

В Chrome проверен выбор E5 в почте и оценке. Интерактивный поиск вернул по 10 результатов в исходном ящике и в обоих архивах EnronQA. На локальном английском архиве повторная загрузка сохранённой матрицы воспроизвела выдачу. Прошли 72 backend-теста с PostgreSQL и 9 тестов CI/CD.

Контрольный запуск из dev API: POST `/dev/api/v1/evaluations` с JSON `{"model":"e5-cosine","dataset":"mail-public"}`. Прогон `dc0c6a280e5c4cd98cee2f4689305d44` завершил 99 из 99 запросов без ошибок. Общий eval, бинарная публичная разметка, макроусреднение. При K = 10 E5 получил Recall 0,321637, nDCG 0,219161, MRR 0,238195. Сохранённый на том же fingerprint результат BM25 с учётом событий составляет 0,937564 / 0,997610 / 1,000000. Чистое семантическое ранжирование заметно уступило этому baseline на публичной почтовой выборке.

Серверный p99 E5 составил 71,264 мс для последовательно отправленных запросов с лимитом 100. Время включает ASGI-обработку, инференс и чтение результатов из PostgreSQL. Индекс уже построен, отдельного прогрева не было, внешняя сеть в замер не входит. Итог API со всеми K сохранён в `api-run.json`, строки сравнения и fingerprint в `comparison.json`.
