# Проверка поиска на пяти ящиках вне публичного набора

Для проверки переноса на новые запросы собрали 60 русских формулировок, по 12 на ящик. Эти пять ящиков отсутствуют среди публичных 99 запросов. Поиск выполнялся по исходному корпусу из 16 376 писем. Запросы и разметку зафиксировали до первого прогона. Получилось 222 положительные пары и 202 уникальных релевантных письма. У 36 запросов по одному эталону. Только у одного запроса все эталоны получены накануне даты сценария.

Разметка использует написанные для каждого запроса условия поиска по содержанию и датам письма. Формулировки основаны на предоставленных письмах, поэтому точные детали и их словесная форма могут благоприятствовать лексическому поиску. Условия проверены на полном ящике. Есть повторяющиеся эталоны, а полнота семантической разметки независимо не подтверждена. Закрытую выборку организаторов команда не видела.

## Сравнение методов

Три конфигурации на `dev` в коммите `ea8c2f4`. Общий офлайн-eval использовал K = 1, 5, 10, 20, 50, 100, макроусреднение и один поиск с K = 100 для каждого запроса. Во всех шести прогонах по двум наборам ошибок не было.

| Метод | Контрольные 60 nDCG@10 | Recall@10 | MRR@10 | Публичные 99 nDCG@10 | Recall@10 | MRR@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 по дате + статус действия | 0,8344 | 0,8870 | 0,8344 | 0,9976 | 0,9376 | 1,0000 |
| BM25 по дате без поправки за статус | 0,8344 | 0,8870 | 0,8344 | 0,9949 | 0,9376 | 0,9949 |
| BM25 по дате + MiniLM 75/25 | 0,8362 | 0,8877 | 0,8343 | 0,9931 | 0,9366 | 0,9949 |

MiniLM по nDCG@10 улучшил 11 запросов из 60, ухудшил 7, в 42 результат совпал. На 36 запросах с одним эталоном его MRR@10 составил 0,8495 против 0,8651 у основного метода. Поправка за статус срабатывает при распознанном дне получения. Для 7 запросов с меткой «статус» в контрольном наборе день получения не указан. На контрольных 60 поправка не изменила метрики ни одного запроса, а на публичных 99 прибавила 0,0027 nDCG@10 к BM25 по дате без поправки.

| Сценарий | Запросов | nDCG@10, BM25 со статусом | nDCG@10, BM25 + MiniLM |
| --- | ---: | ---: | ---: |
| Без даты | 22 | 0,9518 | 0,9178 |
| Дата события в тексте | 10 | 0,8754 | 0,9285 |
| Статус действия | 7 | 0,9617 | 0,9920 |
| Конкретный день получения | 4 | 0,9077 | 0,9077 |
| Диапазон получения | 17 | 0,5889 | 0,5954 |

Для 17 запросов с диапазоном штатный разбор дат вернул отсутствие конкретного дня. Основной BM25 вернул 77 из 170 писем первой десятки за пределами периода, MiniLM — 78 из 170. При этом средний Recall@100 основного BM25 по этим запросам составляет 0,9803. Если взять сохранённые первые 100 кандидатов и отфильтровать по **эталонным границам** из разметки, nDCG@10 на диапазонах поднимается с 0,5889 до 0,8734, а Recall@10 — с 0,6476 до 0,8370. Это диагностика сохранённой выдачи при известных границах. Автоматический разбор диапазона в этом прогоне не участвовал.

## Решение по текущему методу

Оставляем BM25 по дате с поправкой за статус основным. Для MiniLM средняя прибавка на отдельном наборе мала, а поиск без даты и публичный результат ухудшились. Для следующего изменения приоритет — понимать явные и относительные периоды получения, применять их при отборе кандидатов и сохранять в тексте даты событий, счетов и сроков отправки. Следующую версию правил следует подтверждать на новых формулировках, если для разработки использованы ошибки из этого отчёта.

p99 вызова движка на контрольном наборе составил 4,03 мс для основного BM25 и 213,63 мс для MiniLM на Apple M4 Pro. Это последовательный офлайн-прогон без отдельного прогрева, до 100 результатов, с четырьмя потоками модели. Выполнение серверного ограничения под нагрузкой измеряется отдельным прогоном.

## Воспроизведение

Запуски использовали исходный архив организаторов и отдельно подготовленную локальную копию с новыми запросами и qrels. Запросы, разметка и письма остались в локальном checkout. [Контрольные суммы](frozen.sha256) фиксируют аннотации и manifest. Fingerprint контрольного набора — `2fbf150de7ccbb001109a060c6036d33c8349d7e00fd01792c101cc7f699164e`. На одинаковых входах сборка повторяется байт в байт. Штатный `validate` подтвердил ссылки, даты и ящики.

Из корня checkout на `ea8c2f4` установите локальные зависимости и используйте модели из раздела «BM25 по дате + MiniLM» README. Для публичного прогона подставьте `data/raw/mipt_mail_search_participants.zip`. Для контрольного прогона используйте замороженную папку из рабочего checkout.

```sh
uv sync --project backend --locked --extra minilm
python3 infra/docker/fetch_minilm.py --output artifacts/models/minilm
data_for_eval=data/benchmarks/team-holdout-v1/eval
uv run --project backend --locked --extra minilm mailsearch validate --dataset "$data_for_eval"
uv run --project backend --locked --extra minilm mailsearch run \
  --dataset "$data_for_eval" --output reports/quality/runs/check-status
uv run --project backend --locked --extra minilm mailsearch run \
  --dataset "$data_for_eval" --engine mail_search.search.event_aware:create_engine \
  --config /path/to/bm25-routed.json --output reports/quality/runs/check-routed
uv run --project backend --locked --extra minilm mailsearch run \
  --dataset "$data_for_eval" --engine mail_search.search.bm25_minilm:create_engine \
  --config configs/search/bm25-minilm.json --output reports/quality/runs/check-minilm
```

Сохранены исходные `run.json` и `metrics.json` всех шести прогонов, [срезы](slices.json) и [диагностика диапазонов](range-oracle.json). Общий тестовый запуск backend обнаружил 72 теста, из них 24 пропущены.
