# Проверка обучаемой нормализации русского поискового запроса

Проверили, восстанавливает ли обученный на парах «уменьшительное — основа» суффиксный стеммер новые семейства и как перенос основной словоформы в первый поисковый вариант влияет на выдачу почты. Исходная версия — `bd3ad733fceabf0215603c6b0ca87e718cbed780`. Версия со стеммером — `391b83406a432d3f07de768775f0bfb9a708e3eb`. Оба прогона выполнены из чистых checkout. Конфигурация — штатный `configs/search/bm25-event-aware.json` с включёнными исправлением опечаток и нормализацией форм.

## Поиск писем

Тестовый клиент вызывает реальный обработчик `POST /api/v1/mailboxes/{synthetic_user}/search`. Превью возвращало хранилище в памяти с проверкой ящика и даты отсечения. Архив включает 16 376 писем, 99 запросов и 565 записей разметки. Fingerprint `0daa664136d798c1ed2fe50802a7d236f93b4891d56f2353bc5b807b56601665`. Сравниваются первые 10 результатов. Стандартный eval усредняет метрики по запросам. Незашумлённый и искусственно зашумлённый наборы используют одну разметку и те же фильтры. Для второй группы детерминированно внесено по одной перестановке, вставке-дублированию либо пропуску буквы. Разметка недоступна поиску.

| Вход | Версия | Recall@10 | nDCG@10 | MRR@10 | Ошибки API |
|---|---|---:|---:|---:|---:|
| Публичный | Исходная | 0.937564 | 0.997610 | 1.000000 | 0 |
| Публичный | Со стеммером | 0.937564 | 0.997610 | 1.000000 | 0 |
| С опечаткой | Исходная | 0.937564 | 0.993882 | 0.994949 | 0 |
| С опечаткой | Со стеммером | 0.937564 | 0.993882 | 0.994949 | 0 |

У каждого из 99 запросов в обеих панелях совпали значения всех метрик при K = 1, 5, 10. Полностью совпал состав и порядок выдачи в 89/99 исходных и 88/99 зашумлённых запросов. В обеих версиях корректор восстановил ровно исходную строку для 77/99 зашумлённых запросов. После нормализации первого варианта дата получения сохранена в 99/99 обычных и 99/99 зашумлённых запросов. Сюда входят случаи, когда в тексте нет такой даты.

В промежуточном коммите `5bc14088` чистый nDCG@10 составил 0,996968. Единственное снижение метрик пришлось на запрос об отклонённых платежах. На данной дате тематический вариант «оплата» вернул десять релевантных писем, а вариант «платёж» — девять. Сервис обращается к следующей формулировке, если предыдущая дала меньше K результатов. В итоговой версии восстановлен прежний приоритет тематического существительного при поиске. Для глагола «доставили» первым вариантом остаётся инфинитив «доставить», дополнительными идут «доставили» и «доставка». Поэтому публичный dev здесь служит также регрессионным тестом, и мы не оцениваем по нему независимый выигрыш.

Для трёх разных ящиков использованы фиксированные варианты из эксперимента `20261122T123953Z-6968d61e` на дату 2028-09-11. Совпадением считается весь порядок выдачи до 10 писем при непустом эталонном запросе. Из 36 попыток в сравнение вошли 27. В девяти случаях нейтральный запрос не нашёл писем. Совпадений 27 → 27. На дополнительной панели из девяти запросов с формами «штрафик» и составными фразами совпадений 8 → 9. Новая версия вернула для «проверенные документы» ту же выдачу, что и для «проверить документ».

## Перенос на семейства слов

Проверка включает 2206 автоматически извлечённых пар Русского Викисловаря и 2073 связанных компонент графа написаний. Привели регистр и «ё/е» к одному варианту для группировки. Целую компоненту отправили в один из пяти фолдов по SHA-256 идентификатора. Проверили программно нулевое пересечение написаний между обучением и контролем на каждом фолде. Три ранее вручную добавленные пары исключены из обучения. В контроле и обучении по фолдам также нет примеров «штраф». Отдельно проверили это семейство после обучения на всех разрешённых парах. Морфологический словарь OpenCorpora общий и может содержать сами слова, но на контрольном фолде код не обращается к паре «тестовое слово — правильная основа».

| Режим на отложенном словаре | Выдано | Верная основа | Покрытие | Точность среди выданных | Точное совпадение на всех парах |
|---|---:|---:|---:|---:|---:|
| Генерация по суффиксу | 1912 | 1853 | 86.67% | 96.91% | 84.00% |
| Генерация с защитой словарных слов | 1041 | 933 | 47.19% | 89.63% | 42.29% |

В первой строке модель получает именительный падеж уменьшительного и проверяет, существует ли предложенная основа в морфологическом словаре. Во второй — вызывается консервативная ветка для неизвестных слов, которая учитывает падеж и отказывается преобразовывать самостоятельные словарные слова. Отдельный словарный поиск засвидетельствованных пар здесь выключен. Поэтому вторая строка оценивает поведение запасного механизма и не измеряет покрытие всего приложения. Штатный Snowball дал общий стем уменьшительного и основы в 0/2206 парах. Эта отдельная метрика сравнивает два стема. Морфологические части поиска и Snowball решают разные задачи.

Независимые от обучения примеры «штрафик», «штрафчиком», «штрафиках», «штрафчиками» дали «штраф». Генератор без проверки входа предлагал заменить 5 из 24 самостоятельных контрольных слов (например, «график» на «граф» и «заказчик» на «заказ»). Защищённый режим предложил 0 замен. Для преобразования знакомых слов приложение дополнительно использует лексикон подтверждённых отношений и отдельные смысловые расширения, например для «оштрафовать».

## Проверки текста

В восьми фразах проверили основной вариант для разных частей речи. Например, «упаковывают проверенные документы» должно давать «упаковывать проверить документ». Совпадений 1 → 8. При учёте любого из вариантов совпали все восемь примеров в обеих версиях. На двенадцати проверках сохранения текста точных совпадений первого варианта 12 → 10. Два отклонения объясняются выбранным приоритетом лемм. Для «к двум» первым возвращается «к два», для изолированного «стали» — «стать». Исходное «стали» и альтернативное «сталь» также сохранены. В контексте «из стали» нормализация даёт «из сталь», а «они стали работать» даёт «они стать работать». В отдельном историческом наборе из десяти самостоятельных слов, имён и структурированных токенов сохранено 10 → 10. В восьми исторических контрольных контекстах корректор орфографии сохранил 8 → 8 исходных фраз. По 2500 частым словоформам корпуса количества изменённых одиночных входов составили по пять в каждой версии. Часть этих примеров — корпусные сокращения. Разметки качества этих одиночных замен нет.

Публичные 99 запросов и синтетические примеры не оценивают приватный тест, естественное распределение опечаток и полное разнообразие русского языка. Контроль неоднозначных слов проверяет только перечисленные примеры. Фолды исключают общие известные графу написания и основы. Совпадение корней у лингвистически родственных, но несвязанных в этом словаре слов возможно.

## Воспроизведение

Запускать из чистого checkout соответствующего SHA. `JOURNAL` — абсолютный путь к этой папке записи из отдельного checkout ветки team-memory, `DATA` — архив `mipt_mail_search_participants.zip`, `OUTPUT` — новый каталог отдельно для базовой и новой версий.

```sh
uv sync --project backend --locked
PYTHONPATH=backend/src backend/.venv/bin/python "$JOURNAL/check.py" "$DATA" "$OUTPUT"
PYTHONPATH=backend/src backend/.venv/bin/python "$JOURNAL/audit.py" "$DATA" "$OUTPUT/corpus_spelling.json"
```

На новой версии выполнить проверку переноса и сравнение ранее сохранённых каталогов. Переменная `BASE_OUTPUT` указывает на результат первого запуска.

```sh
PYTHONPATH=backend/src backend/.venv/bin/python "$JOURNAL/heldout.py" backend/src/mail_search/application/ru_diminutives.tsv "$OUTPUT"
python3 "$JOURNAL/compare.py" "$BASE_OUTPUT" "$OUTPUT"
```

В `baseline/` и `candidate/` сохранены метаданные общего eval, метрики при K = 1, 5 и 10 и диагностические панели. Файл `comparison.json` содержит сравнение запусков, `candidate/holdout.json` — результат по фолдам и контрольным словам. При воспроизведении общий eval также создаёт полные предсказания и отчёт по каждому запросу.
